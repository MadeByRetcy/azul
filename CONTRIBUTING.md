
# 👋🏼 Azul Contribution Guidelines (ACG)

### ℹ️ Introduction

Thank you for considering contributing to the project. Contributing makes Azul such a great tool for you, us and the broad Moroccan community.

**It's easy to get started once you read this document!** Following the instructions helps creating mutual respect between all of us and being understanding of each other. we welcome any type of contribution (bug fixes, documentation...) that will help this project improve!

However, please keep in mind this Github repo is only for reporting issues related to Azul and pushing changes that have been communicated and discussed with the team.

### ⚖️ Rules

1. 💻 Code:

To contribute to the website or any non-icon asset, please follow these basic rules:
- Try your best to **account for edge cases** in code, if you can't you can try to extensively test your code to find those edge cases.
- Speaking of edge cases, **make sure you test all of you code**, unit testing is primarily used.
- Keep variable, function and type names **simple and clear, and representative of their purpose.**
- Commit messages **should respect the [Conventional Commits Specification.](https://www.conventionalcommits.org/en/v1.0.0/)**
- Apply the **DRY (Don't repeat yourself), SOLID (Methods should perform one action) & KISS (Keep it short and simple)** Paradigms
- **Use [atomic commits](https://www.aleksandrhovhannisyan.com/blog/atomic-git-commits)** when possible to avoid unnecessary issues.         
- It's preferable if you use **4 Tabs indentation** and **adhere to common programming conventions** (Primarily JS/TS, CSS, HTML...) and **format your code appropriately** with [Prettier.](https://prettier.io/)
- When using TypeScript, **use types whenever possible!**

2. 🖼️ Icons:
>
> [!IMPORTANT]
> 
> By contributing free icons to our open-source project, **you grant us permission to create a variants of your design for the Azul Itri subscription service.** This helps us develop the project and make it sustainable long term!
>
To contribute or suggest an icon for **the free, publicly available icons**:
- Always use a `2px` stroke, and a black color.
- You're free to use any vector editor you desire, the primary tool is Inkscape.
- Always icons that are rounded playful and have ties to Moroccan culture, at the moment we're not planning to create any non-Morocco related icons but that may change in the future.
- To keep with consistency, icon SVGs should `29px x 29px`

### 🐣 Your First Contribution

Unsure where to begin contributing to Azul? You can start by doing the following:
- Report inconsistencies with the icons
- Fix typos in the documentation
- Suggest new icons

Feel free to ask for help; everyone is a beginner at first :)


### 🦟 Reporting a bug

>
> [!CAUTION]
> **Report security issues/exploits by emailing us at support@msharf.in with `[AZUL-VULN] ...`.**\
> To determine a security issue, the answer to these questions should be _YES_:
> - Does the issue contains sensitive data?
> - Are you accessing something you shouldn't access?

Filing a bug report, suggestion or issue is as simple as going to the Issues tab and choosing the appropriate template for your inquiry!

Though make sure your issue/suggestion hasn't been filed by someone else to avoid duplicates and streamline our work process.


### 🔍 Code review process

The Azul core team and maintainers have the final say on whether a code snippet or an icon should be merged or not, if the latter has been rejected don't panic! You would get a helpful explanation on how to make it better.
